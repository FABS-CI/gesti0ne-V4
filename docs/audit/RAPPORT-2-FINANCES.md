# Rapport d'audit — Module Finances (GESTIONE V4)

Date : 30/10/2026 · Branche : `audit/finances` (basée sur `audit/comptabilite`) · Migration :
`0109_finances_integrite.sql`

Deuxième étape de l'audit, après la Comptabilité (`RAPPORT-1-COMPTABILITE.md`). Même méthode :
état établi à partir des migrations et de `types.ts`, faute d'accès à la base ; corrections
idempotentes ; tests sur un vrai PostgreSQL (PGlite) dans
`src/lib/finances/integrite-finances.test.ts` (9 tests), chaque anomalie étant reproduite
avant correction.

## Périmètre vérifié

- **Transactions** (écran Finances : recettes et dépenses) : saisie, modification, suppression,
  totaux, solde.
- **Paiements clients** : comptabilisation, dé-validation, garde-fous existants (anti-surpaiement,
  validation, interdiction de suppression, journal d'audit).
- **Achats** : comptabilisation (un seul déclencheur, conforme).
- **Interaction Finances ↔ Comptabilité** : qui crée les écritures, risques de doublon.

## Calculs contrôlés

- Une écriture par facture et par paiement (montants, comptes 411 / 701 / 571 / 521).
- Contre-passation d'un paiement dé-validé : l'écriture active disparaît, l'historique reste.
- Totaux de l'écran Finances : recettes et dépenses validées seulement.
